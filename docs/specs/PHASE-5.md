# PHASE 5: Collection

## Goal
Get evidence from endpoints into the platform with its integrity provable end to end (guide 9):
a live triage collector for Windows (PowerShell 5.1) and Linux (Python 3, stdlib only) that is
read-only toward the host and writes a hashed `manifest.json`; server-side ingest of the
resulting triage bundle that treats the bundle as hostile input, verifies every member against
the manifest, turns each parseable member into *derived evidence* (own custody chain, linked to
the bundle) and sends it through the existing Phase 2 parser pipeline so it lands in the
timeline; and documented, tool-checking wrappers for memory and disk acquisition.

## In scope / Out of scope
In scope: `collector/collect-windows.ps1`, `collector/collect_linux.py`, the shared manifest
schema `dfirbench.triage/1`; acquisition wrappers `collector/acquire/acquire-memory-windows.ps1`
(WinPmem), `collector/acquire/acquire-memory-linux.sh` (AVML), `collector/acquire/acquire-disk-linux.sh`
(ewfacquire, else dc3dd, else dd); `docs/collection.md` (order of volatility, collector usage,
manifest schema, acquisition procedures, upload + ingest); bundle safety + manifest verification
(pure module), bundle ingest job (worker), derived evidence with parent link, `bundle_members`
record, collector trust list outside the DB, migration `0008`, API changes below, a small UI
change (Process on a triage bundle starts the ingest; derived items show their parent), tests,
live smoke.

Out of scope (see `docs/BACKLOG.md`): tar/7z/E01-in-bundle formats (ZIP only), raw NTFS reads /
VSS for locked files (`$MFT`, `Amcache.hve`, `SRUDB.dat`, loaded hives of other users are
recorded as collection errors), parsers for the other collected artifacts (registry, prefetch,
LNK, browser, journal/wtmp, shell history: Phase 6), macOS collector, remote agent, cloud/SaaS
collectors, Windows disk-imaging wrapper (documented procedure only), memory-image processing
(Volatility, Phase 6), signed collector releases (Authenticode / minisign), evidence status derived
from jobs, resumable uploads.

## Standard-profile decisions (made without the owner; recorded here)
1. **Linux collector in Python, not bash.** Stdlib only, Python >= 3.6. JSON and SHA-256 are
   reliable in Python; a bash manifest writer needs `jq`/escaping that is easy to get wrong. The
   acquisition wrappers are bash because they only orchestrate an external tool.
2. **Bundle format is ZIP only** (`stored`/`deflate`), `manifest.json` at the root. Tar and other
   archive types are refused (`unsupported_archive`), which also removes tar hard links/devices.
3. **Derived evidence instead of a bundle parser.** Each verified member that a registered parser
   recognizes is copied from the scratch dir into the WORM vault at
   `{case}/{bundle}/derived/{derived_id}/{safe name}`, recorded as a new evidence row with
   `parent_evidence_id` = bundle, and gets its own signed custody chain (`created` with provenance,
   `ingested`, `hash_verified`, `locked`). A normal parse job is queued for it, so the existing
   pipeline (custody + hash re-verification before parsing, run manifests, fencing, detection
   trigger) is reused unchanged. Members with no parser are verified and listed, not copied.
4. **Unsafe archive = whole bundle rejected** (job `failed`, admins notified, `processed` custody
   entry with the reasons). **Manifest mismatch = member quarantined**: a hash/size mismatch, a
   listed-but-missing or an unlisted member is never ingested; the job ends `partial`, the member
   is recorded in `bundle_members`, and admins are notified. The bundle object itself stays
   untouched in the vault.
5. **No credential material is collected** (guide 9.2 rule 5): no SAM/SECURITY hives, no
   `/etc/shadow`, no browser `Login Data`/`Cookies`, no key files other than `authorized_keys`.
6. **Collector trust anchor outside the DB**: `app/collection/trusted_collectors.json` (packaged,
   regenerated by `scripts/update-collector-hashes.py`, checked by a unit test) plus an optional
   operator file `COLLECTOR_TRUSTED_HASHES_PATH`. The PowerShell script is listed with both CRLF
   (git checkout, `.gitattributes`) and LF bytes. An unknown collector hash is a warning
   (`collector_unverified`), not a rejection (modified collectors are legitimate in the field).
7. **Collector clock offset** is only measured when the operator names a server
   (`-NtpServer` / `--ntp-server`); otherwise local time-sync status is recorded. No network
   calls by default.
8. **Evidence grants tightened** (the new `parent_evidence_id` must be immutable for the app):
   the app role loses DELETE and table-wide UPDATE on `evidence` and keeps UPDATE only on the
   columns the upload/finalize/verify flow writes.

## Manifest (`dfirbench.triage/1`)
```json
{"schema": "dfirbench.triage/1",
 "collector": {"name": "dfirbench-collect-linux", "version": "1.0.0", "sha256": "<script>", "runtime": "python 3.12.1"},
 "host": {"hostname": "web01", "fqdn": "web01.corp.local", "os": "Ubuntu 22.04.4 LTS",
          "timezone": "Europe/Berlin", "utc_offset_minutes": 120, "boot_time": "...Z"},
 "operator": "alice", "case_ref": "IR-2026-001", "mode": "live|offline", "elevated": true,
 "started_at": "2026-09-29T10:00:00Z", "finished_at": "2026-09-29T10:03:12Z",
 "clock": {"source": "timedatectl", "synchronized": true, "ntp_offset_s": null},
 "files": [{"path": "logs/auth.log", "sha256": "<64 hex>", "size": 2231, "category": "logs",
            "source": "/var/log/auth.log", "collected_at": "...Z"}],
 "errors": [{"target": "/etc/sudoers", "error": "PermissionError"}],
 "skipped": [{"target": "/var/log/journal", "reason": "symlink"}]}
```
Strict validation: `schema` literal, times ISO-8601 with zone, `path` safe (same rules as archive
names), `sha256` 64 hex, `size >= 0`, `files` <= `BUNDLE_MAX_MEMBERS`, unique paths; unknown
top-level keys are ignored (forward compatible); strings are bounded.

## Bundle ingest (worker, `BundleIngestService.run`)
1. Claim (`kind='bundle'`, same fencing token as parse jobs). Evidence must be `stored`, kind
   `triage_bundle`, case open. The bundle is streamed from its recorded vault version into the
   job scratch dir and must match the signed `ingested` SHA-256 (same `fetch_verified` as
   parsing; a mismatch writes `hash_failed`/`verification_failed` custody).
2. **Inspect** (no bytes extracted yet), reject the bundle if any holds:
   not a ZIP / ZIP64 inconsistencies / encrypted member / compression other than stored+deflate;
   member name absolute (`/x`), drive letter (`C:`), backslash, `..` or `.` component, empty
   component, NUL/control character, longer than 512 chars or 32 components; duplicate names
   (also case-insensitively); symlink or any non-regular, non-directory unix mode (hard links,
   devices, FIFOs); overlapping or duplicate local header offsets; more than
   `BUNDLE_MAX_MEMBERS` (default 10 000); declared total > `BUNDLE_MAX_TOTAL_MB` (4096); a member
   > `BUNDLE_MAX_MEMBER_MB` (2048); a member's or the archive's compression ratio >
   `BUNDLE_MAX_RATIO` (200, for members > 1 MiB); no `manifest.json` at the root, manifest >
   16 MiB or invalid.
3. **Extract + verify**: each member is streamed to `scratch/members/NNNNN.bin` (fixed names, never
   derived from content, `O_EXCL`, 0600 then 0400) while hashing and counting bytes against the
   declared size and the running total (the declared sizes are not trusted). Result per member:
   `verified`, `hash_mismatch`, `size_mismatch`, `corrupt` (CRC/deflate error), `unlisted`;
   manifest entries without a member are `missing`.
4. **Derive**: for each `verified` member, `registry.detect(head, basename)`; if a parser matches,
   the file is uploaded to the vault (outside any DB transaction), then in one transaction under
   the job row lock (token re-checked) and `FOR SHARE` on the case (re-checked open): evidence row
   (`stored`, `parent_evidence_id`, `source_host` = bundle's or manifest host, `acquired_at` =
   member `collected_at`, `acquisition_tool` = collector), custody `created` (provenance: bundle
   id + SHA-256, member path, manifest SHA-256, job id), `ingested`, `hash_verified` (bytes vs
   manifest vs extraction), `locked` (vault retention), a `bundle_members` row and a parse job
   (params: `timezone` from the manifest when it is a valid IANA zone for `linux_auth`). A member
   already derived by an earlier run of the same bundle (same path + SHA-256, evidence `stored`)
   is reused, and its parse job is resubmitted idempotently. Parse jobs are dispatched after
   commit. Caps: `BUNDLE_MAX_DERIVED` (500).
5. **Finish** under the job lock: status (`succeeded`, or `partial` when any member is flagged;
   errors the collector itself reported do not make the run partial), run manifest
   (collector, trust, host, times, counts by status, flagged members (<= 200), derived ids,
   limits, collector error count + samples) and a signed `processed` custody entry on the bundle
   (manifest SHA-256, counts, flagged paths, derived evidence ids). Flagged members or a rejected
   bundle also notify admins (`evidence.bundle_rejected`, `evidence.bundle_manifest_mismatch`).

## Data model changes (`0008_collection.py`)
* `evidence.parent_evidence_id` (FK evidence, nullable, index): set at insert only.
* `bundle_members`: `id`, `case_id`, `bundle_evidence_id`, `job_id`, `attempt`, `member_path`,
  `member_index`, `size_bytes`, `sha256_manifest`, `sha256_actual`, `status` (CHECK:
  ingested|verified|hash_mismatch|size_mismatch|missing|unlisted|corrupt), `parser`,
  `derived_evidence_id`, `parse_job_id`, `detail` jsonb, `created_at`; UNIQUE
  `(job_id, attempt, member_path)`; index `(bundle_evidence_id, member_path)`.
* `jobs`: partial unique index `uq_jobs_active_bundle (evidence_id) WHERE kind='bundle' AND status
  IN ('queued','running')`.
* Grants for `dfirbench_app`: `bundle_members` SELECT, INSERT only (a verification record is never
  rewritten); `evidence`: REVOKE UPDATE, DELETE, TRUNCATE, then GRANT UPDATE (sha256, md5,
  size_bytes, storage_version_id, mime_type, status, retain_until). No new SECURITY DEFINER
  functions.

## Collector rules (both collectors, tested)
Read-only toward the host: no delete/modify/move of anything outside `-OutputDir`/`--output`;
PowerShell uses `-LiteralPath` and .NET reads with `FileShare.ReadWrite|Delete`; Python opens with
`O_RDONLY|O_NOFOLLOW|O_NONBLOCK` (+`O_NOATIME` when permitted), checks `S_ISREG` after `fstat`,
never follows symlinks. Exported data (`wevtutil epl`, `reg save`) goes only into the output
directory; the only deletion the Windows collector performs is its own staging folder inside the
output directory after the zip is written and re-hashed (`-KeepStaging` keeps it). Locked or
unreadable targets are recorded in `errors` and collection continues. Every file gets a SHA-256
and size in the manifest; the manifest records collector version + own SHA-256, host, operator,
UTC start/end, timezone and clock status. Per-file and total size caps. PowerShell: 5.1 syntax
only (checked with the 5.1 parser), ASCII-only source.

## Test plan
* Unit (no Docker): archive-name rules (hypothesis: never raises, accepted names never escape);
  malicious fixture bundles (`tests/fixtures/bundles/`: traversal x5 variants, symlink, bomb by
  ratio / total / count, duplicate + case-duplicate names, encrypted, overlapping headers, hash
  mismatch, size mismatch, missing, unlisted, no/invalid manifest, tar) and a good bundle;
  extraction writes only fixed names inside the destination; manifest schema; collector trust
  list matches the scripts; Linux collector against a fake root (hashes verify through the ingest
  module, unreadable file -> error, symlink skipped, nothing written outside `--output`, source
  tree unchanged); Windows collector (skipped without `powershell.exe`): 5.1 parser finds no
  errors, a quick run produces a bundle that verifies; wrappers exit 2 with a clear message when
  the tool is missing and contain no download commands.
* Integration (compose Postgres, fake vault): upload a collector bundle -> `/process` -> bundle job
  -> derived evidence (parent link, verifiable custody, WORM) -> parse jobs -> events in the
  timeline; rerun reuses derived items; hash-mismatch bundle -> `partial`, member quarantined,
  admins notified; traversal/symlink/bomb bundles -> `failed`, nothing derived; closed case;
  RBAC (viewer 403, outsider 404); app-role denials on `bundle_members` and `evidence`; migration
  round trip.
* Live: `scripts/phase5-smoke.py` (Linux collector run on a fixture root -> upload -> ingest ->
  derived parse jobs -> events searchable; malicious bundles rejected; custody verifies).
